# 筆を穂先と腹の2室にする(検討)

2026-11-01、[筆と紙の水のやり取りを1本の式にする](2026-11-01-brush-exchange.md)(以下「受け渡しの式」)を実装した直後の検討メモ。この時点で受け渡しの式は作業ツリーにあり、未コミット。

動機: 受け渡しの式で量は釣り合うようになったが、乾きかけの筆で濡れた色を吸っても、その色を運んで置けない。比較(e2e `paint_brush_picks_up_wet_color`、水 5% の透明な筆で黄の溜まりを通した後):

| 筆の大きさ `brush_hold` | 通った後の筆の水 | 筆の色の濃さ(溜まり = 1) |
|---|---|---|
| 2000px(既定) | 7.8% | 0.38 |
| 1000px | 10% | 0.54 |
| 600px | 13% | 0.65 |
| 300px | 17% | 0.77 |

溜まりの中には筆が吸い取った白っぽい筋ができる(吸い取りは効いている)が、溜まりの先の線はどの大きさでもごく淡い。吸える量は溜まりの水で頭打ちになり、筆の容量に比べてわずかなので、筆全体は乾きかけのまま。実物の筆は穂先に吸った色水をすぐ紙へ出す。1室のモデルにはその穂先がない。

ユーザーの選択: 案 A(穂先と腹の2室)。全体の色が薄くなった件(受け渡しの式では筆跡の重なりで顔料が積み上がらない)は、いったん薄いままでよい(`brush_pigment` の既定値は今は上げない)。

---

## 1. 状態

筆を2つの入れ物に分ける。どちらも今の単位(水 1 = その室が満タン、顔料 1 = 満タンの水に標準の1回分)で持つ。

| 室 | 水 / 顔料 | 容量(紙のセルの量) | 役割 |
|---|---|---|---|
| 穂先 | `W_t` / `P_t` | `C_t` = `brush_tip` × 1.6r × w_sat ÷ ln2 | 紙と受け渡す。小さい |
| 腹 | `W_r` / `P_r` | `C_r` = `brush_hold` × 1.6r × w_sat ÷ ln2 | 穂先へ水を送る。大きい |

`brush_tip` / `brush_hold` はどちらも「満タンの室だけで乾いた紙をこの長さ塗ると半分になる」長さ(px)。容量の式は受け渡しの式と同じ。

## 2. 1フレームの流れ

1. **穂先と紙の受け渡し**(splat.wgsl、splat ごと・セルごと): 受け渡しの式のまま、筆の濡れ具合を穂先の `s_t = W_t` に置き換える
   ```
   f = brush_exchange × coverage × 筆圧 × (s_t − s_p) × w_sat
   f > 0: 穂先 → 紙(顔料は穂先の濃さで出る)
   f < 0: 紙 → 穂先(浮遊顔料は紙の濃さで入る。穂先の渇き 1 − s_t を掛ける)
   ```
   フレーム内の予測(受け渡しの式 §6 の (e))も穂先の容量で行う(`Splat.scale` = 穂先の残りの予測)
2. **集計を穂先へ反映**(brush.wgsl): 受け渡した量 ÷ `C_t` を穂先に足し引きする
3. **腹から穂先へ補充**(brush.wgsl): 腹が穂先より濡れていれば、濡れ具合の差を時定数 `brush_refill_time`(秒)で詰める向きに水を送る。顔料は腹の濃さで一緒に動く
   ```
   移る水(紙のセルの量)= (1 − exp(−dt / τ)) × max(s_r − s_t, 0) × C_t × C_r / (C_t + C_r)
   ```
   `C_t × C_r / (C_t + C_r)` は、差を詰め切ったときに2室の濡れ具合が揃う量。量は保存する(腹から出た分だけ穂先が増える)

## 3. ここから出てくる動き

- **乾きかけの筆で吸って運ぶ**: 穂先は小さいので、濡れた溜まりを通るとすぐ溜まりの色で満ちる。満ちた穂先はその濃さのまま次の所へ置ける。運べる長さは穂先の大きさで決まる(`brush_tip` = 150px なら 150px ほどで半分)
- **長く塗り続けられる**: 穂先が減ると腹が送るので、全体の持ちは腹の大きさで今のまま
- **速く長く引くと穂先が追いつかずに淡くなる**: 穂先から出る速さが腹からの補充を上回ると、ストロークの途中で淡くなり、ゆっくりにすると戻る(実物の「かすれ」に近い)。どれくらい出るかは `brush_tip` と τ で決まるので、ふつうの速さで目立たない値を e2e で探す
- **筆の汚れは穂先に残る**: 補充は腹 → 穂先の一方向なので、吸った色は穂先にとどまり、紙へ出し切るまで続く。腹の色は変わらない(§5-1)

## 4. 変わる所

- **GPU の筆バッファ**: 32B → 64B(穂先と腹それぞれに水 + 顔料 vec4)
- **ヘッダ**: 空いている2枠のうち1つを `brush_dt`(この brush パスで補充に使う秒数)にする
- **SimParams**: `brush_tip`(穂先の大きさ、px)と `brush_refill_time`(腹から穂先へ送る時定数、秒)の2フィールド。224B に空きは1枠なので、末尾パディングを足して 240B にする
- **`BrushLoad`**: 穂先(`tip: { water, pigment }`)を足す。色を取る・水に浸す・洗うは、穂先と腹に同じ操作をする(同じ単位なので、どちらも同じ濡れ具合・同じ濃さになる)。保存・記録・自動補充の戻り先は穂先ごと持つ。JSON は `#[serde(default)]` で、穂先の無い古い記録・保存は「穂先 = 腹と同じ」として読む
- **CPU の予測**: `brush_release_max` を穂先の容量で計算する
- **筆の状態パネル**: 穂先の水と腹の水の2本のゲージ。色見本と濃さは穂先(次に置く色)を出す。顔料の積み上げゲージは腹

## 5. 決めること

1. **補充の向き**: 腹 → 穂先の一方向にするか、穂先が腹より濡れていれば穂先 → 腹にも戻すか
   - 一方向(推奨): 吸った色は穂先にとどまり、紙へ出し切るまで運べる。腹の色は変わらない
   - 両方向: 吸った色が腹へ薄まって戻るので、運べる長さは短くなるが、筆全体がゆっくり汚れていく
2. **筆を上げている間の補充**: brush パスは塗るフレームでしか走らないので、筆を上げている間は補充されない。案は、CPU が前回の brush パスからの経過時間(刻み数 ÷ 60、上限 2 秒)を `brush_dt` で渡し、次に塗るフレームの brush パスでまとめて補充すること。描き始めの1フレームだけは補充前の穂先で置かれる。毎フレーム brush パスを回す案もあるが、中身が毎フレーム変わるので、色・水・洗うを押すたびに GPU の完了を待つことになる
3. **既定値**: `brush_tip` = 150px、`brush_refill_time` = 0.3 秒から始めて、e2e(吸って運ぶ・ふつうの速さで途中が淡くならない)と目視で決める
4. **時間の基準**: 補充はシミュの刻み(1/60 秒)で数え、モニタのリフレッシュレートに依らないようにする(記録の再生でも同じ結果になる)

## 6. 決定と既定値(同日)

§5 はすべて推奨どおりに決定(補充は腹 → 穂先の一方向、筆を上げている間の補充は次に塗るフレームでまとめて(上限 2 秒)、時間はシミュの刻み)。

既定値は e2e で決めた(headless 512²。「普通の速さ」は e2e のストロークのテンポ = 2 フレームで 10.8px ≈ 324px/秒、満タンの青で乾いた紙を 300px):

| 穂先 / 補充の時定数 | 300px 後の穂先の水 | 300px 後の腹の水 | 水 5% の透明な筆が黄の溜まりを通った後の先の線(彩度、溜まりなし 0.024) |
|---|---|---|---|
| 150px / 0.3 秒 | 0.74 | 0.96 | 0.057 |
| 60px / 0.02 秒 | 0.91 | 0.93 | 0.070 |
| 80px / 0.05 秒 | 0.88 | 0.94 | 0.070 |
| 40px / 0.02 秒 | 0.91 | 0.93 | 0.063 |

- 穂先 150px・0.3 秒は、普通の速さで穂先の補充が追いつかず(穂先 0.74)普段の線が淡くなる。補充は一方向なので、速くしても吸った色は腹へ薄まらない
- 穂先の大きさを 40〜80px で変えても、溜まりの先へ運ぶ色はほぼ同じ。溜まりを出た直後の線は溜まりとほぼ同じ濃さで、150px ほどかけて淡くなる。先の線が淡く見えるのは、受け渡しの式で全体が薄くなった分(溜まり自体が淡い)
- 既定は **穂先 80px・補充 0.05 秒** にした
