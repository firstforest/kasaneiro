# 筆と紙の水のやり取り — 置く・減る・吸うを1本の式にする(検討)

2026-11-01、塗る筆が紙から色を吸う機能(コミット c0ef883)を入れた直後の検討メモ。動機はユーザーの指摘:

1. 「筆の水や顔料が減らないです。描いたらすぐに吸ってしまってるかも」(→ 換算を直して解消)
2. 「乾きかけの筆で吸うのがあまり起きないかも」
3. 「ちょっとアルゴリズムをちゃんと考えたいです」

この時点では未実装。決めることは §5。

関連: [design.md](../design.md) §3.8(筆の中身)/ [parameters.md](../parameters.md) §1(筆のパラメータ)/ [note/05](../note/05-wet-spreading.md)(毛細管拡散と筆の含み)

---

## 1. 今の仕組み(c0ef883 時点)

塗る筆の中身は GPU の筆バッファにあり(水 W: 1 = 満タン、顔料 P: 1 = 標準の1回分)、次の3つが別々の約束で動いている:

| 動き | 決め方 | 量の単位 |
|---|---|---|
| 置く | splat ごと・セルごとに `brush_water × W × coverage` の水と `brush_pigment × P × coverage` の顔料を**足す**(筆からは引かない) | 紙のセルの量 |
| 減る | なぞった距離で `0.5^(距離 / brush_hold)` を掛ける(CPU が splat ごとの残りの割合 `scale` を渡す)。置いたままは `brush_charge` 秒で水を使い切る(feed splat) | 筆の割合 |
| 吸う | 紙の水位が「この筆で1回なぞったときの水位」(`brush_water × W × 重なり 6.4`)を超えたセルから、超えた分 × `brush_absorb × coverage × 筆圧 × (1 − W)` を取り、浮遊顔料も同じ割合で持っていく。合計を「満タンの筆が一生で置く量」で割って筆に足す | 換算して筆の割合へ |

## 2. 診断: 置く量と減る量がつながっていない

置く量(紙の単位)と減る量(筆の割合)の間に換算がないので、**吸った量を筆の何割と数えるかに正解がない**。換算をどこに置いても辻褄が合わない所が出る:

- **筆跡1つの量を 1 とした場合**(最初の実装): 半径 16px・間隔 4px・`brush_hold` 2000px の筆は、中身が尽きるまでに筆跡を約 2000 / (ln2 × 4) ≈ 720 個置く。置いた量の約 720 倍を吸った扱いになり、少し吸うだけで満タンに戻った。さらに吸うかどうかを筆跡1つの水位と比べていたので、1回なぞると約 6.4 回重なる自分の水を常に吸い戻していた。結果、**筆が減らなかった**
- **一生で置く量を 1 とした場合**(c0ef883): 置いた分以上は戻らないので減るようにはなった。代わりに筆が大きな貯水タンク扱いになり、e2e(`paint_brush_picks_up_wet_color`)では水 5% の筆が黄の溜まりを通っても水 9% にしかならない(濃さは約 0.65 まで染まる)。紙の溜まりは全体に淡くなり、吸った色は筆の中で薄く延ばされて先の線も淡い。**吸うのが見えにくい**
- 自動補充 on(既定)では筆を下ろすたびに満タンへ戻るので、乾きかけの筆になる場面自体が少ない

置く側も、筆跡ごとに筆の中身に比例した量を「足す」だけなので、満タンの筆で濡れた所を何度もなでると紙の水はいくらでも増える(釣り合いがない)。置いたまま流れ出る feed splat は、これを目標水位への `max` 補充で抑える特別扱いになっている。

## 3. 案: 筆と紙の間の水のやり取りを1本の式にする

筆を容量の決まった水の入れ物として扱い、置くのも吸うのも同じ式で決める。量はやり取りで保存する。

**状態**

- 筆: 水 `W_b`、顔料 `P_b`(4色)。容量 `C`(紙のセルの量の単位)。濡れ具合 `s_b = W_b / C`
- 紙のセル: 水 `w`、浮遊顔料 `p`(4色)。濡れ具合 `s_p = w / w_sat`(`w_sat` = 紙が満タンに濡れた水位)

**splat ごと・セルごとの受け渡し**

```
f = k × coverage × 筆圧 × (s_b − s_p) × w_sat      // 移る水(セルの量)
f > 0: 筆 → 紙。  w += f、 p += f × (P_b / W_b)       // 顔料は筆の濃さで一緒に出る
f < 0: 紙 → 筆。  w += f、 p += f × (p / w)          // 浮遊顔料は紙の濃さで一緒に入る
```

セルごとの受け渡し(水と4色)を atomic で合計し、フレームの最後に brush.wgsl が `W_b −= Σf`、`P_b −= Σ顔料` とそのまま引き算・足し算する。換算の基準は要らない。

**1本の式から出てくること**

- **減る**: 乾いた紙(`s_p` ≈ 0)に置くと出て減る。濡れた所では差が小さいのであまり減らない。`brush_hold`(距離で減らす)は不要になり、筆の大きさ `C` が代わる
- **置いたまま流れ出る**: 置いたままでも毎フレーム同じ式で、紙と釣り合うまで出続け、出た水は毛細管拡散が外へ運ぶ。feed splat の特別扱い(`max` 補充・`CHARGE_PIGMENT`・`brush_charge`)は要らなくなる。CPU は動かないフレームにも同じ位置の splat を出すだけ
- **吸う**: 紙のほうが濡れていれば(`s_p > s_b`)自然に吸う。満タンの筆は吸わず、乾きかけの筆はよく吸う。吸った量はそのまま筆の量なので、ゲージが素直に動く
- **自分の水を吸い戻さない**: 釣り合った所で受け渡しが止まるので構造上起きない。何度なでても紙の水は `s_b` の水位で止まる(水が増え続けない)
- **濃さ**: 出るときは筆の濃さ、入るときは紙の濃さで顔料が動くので、乾きかけの筆が濡れた色を吸えばその色の筆になり、その濃さのまま次の所へ置ける

**単位**: UI と `BrushLoad` は今の単位(水 1 = 満タン、顔料 1 = 標準の1回分)のまま、GPU 側で `W_b = W × C`、`P_b = P × C × (brush_pigment / brush_water)` と換算すれば、標準の1回分を取った満タンの筆が今と同じ濃さ(顔料 ÷ 水 = `brush_pigment / brush_water`)で置ける。

**筆の大きさ `C` の決め方**: 「満タンの筆で乾いた紙を何 px 塗れるか」(`L`)で指定すると直感的。乾いた紙を1回なぞると幅 ≈ 2 × 0.8r の帯が `s_b` の水位まで濡れるので、`C ≈ w_sat × 1.6r × L × (平均の濡れ具合)` の見積もりで `L` から決める。`brush_hold` の「なぞると半分」と近い感覚でスライダーにできる。

## 4. 実装の見通し

c0ef883 の土台(GPU の筆バッファ・atomic の集計・brush.wgsl・非同期の読み戻し・`BrushFrame`)はそのまま使える。変わるのは:

- splat.wgsl の描画分岐: 「置く(+=)」「吸う」を受け渡しの式1本に置き換え、出た分と入った分を両方集計する
- brush.wgsl: なぞった減り(`brush_scale`)・含み(`feed_dt`)・換算をやめ、集計をそのまま足し引きする
- CPU: `BrushFrame::drag` の距離による減りと feed の時間をやめ、動かないフレームにも splat を出す。`Splat.scale` / `Splat.feed` / ヘッダの `brush_scale` / `feed_dt` は不要になる
- パラメータ: `brush_hold`・`brush_charge`・`brush_absorb` が消え、筆の大きさ(`L` か `C`)と受け渡しの速さ `k` が加わる。`brush_water` は「1筆跡の水量」から `w_sat`(紙をどこまで濡らすか)の意味に変わる
- 初速(`brush_velocity`)・色の溶かし戻し(`paint_pickup`)・空の筆は何もしない、はそのまま

## 5. 決めること

1. **`w_sat`(紙が満タンの水位)を何にするか**: 満タンの筆で乾いた紙を1回なぞった後の水位が自然。ただし毛細管拡散と蒸発で実際の水位は理屈の値(`brush_water × 重なり` ≈ 3.2)より下がるはずなので、今の描き味(水量 0.5 の塗りが約1分濡れたまま、`evap_rate` の調整の前提)を保つには、1回なぞった後の水位を headless で計測してから決める
2. **顔料が水と同じ割合で出入りするか**: 同じ割合が最も単純。毛に残りやすい・出やすいといった個性を付けるなら係数を1つ足す(今は要らないと思う)
3. **フレーム単位で更新するときのずれ**: splat はフレーム頭の `s_b` で受け渡しを決めるので、速く描いて1フレームの splat が多いと筆に残っている以上を出しうる。
   - (a) 出す量の合計が中身を超えたら、brush.wgsl で中身を 0 で止める(紙側は出しすぎたまま。少量なら目立たない)
   - (b) splat パスを2回に分け、1回目で出す量の合計だけを見積もり、2回目で中身に収まるよう縮めて実際に置く(正確。splat パスのコストが倍)
   - (c) 1 splat あたりの `k` を小さく抑え、1フレームで出す量が中身に比べて十分小さくなるようにする(近似。描き味に効く `k` を制約する)
   - (d) 1フレームの splat を数個ずつの組に分け、組ごとに splat パス → brush パスを回す(正確さは組の大きさで決まる。dispatch は splat 数に比例して増えるが、ゆっくり描くフレームは1組で済む)
   - (e) **乾いた紙に置いた場合の減り(=減りの上限)を CPU が splat ごとに予測し、残りの割合として渡す**(今の `Splat.scale` の仕組みを流用)。乾いた紙では1 splat で出る水は筆の中身に比例する(`k × 筆圧 × 被覆の面積 × w_sat × s_b`)ので、筆圧の列から「この splat を置く時点の残り」を前から順に掛けて出せる。実際の受け渡しはこれまでどおりフレームの最後に集計で確定する。濡れた所では実際の減りは予測より小さいので、そのフレームの中では筆を少なめに見積もって置く(次のフレームで正しい中身に戻る)。予測が減りの上限なので、**筆に残っている以上を出すことは起きない**。ずれはフレーム内の、濡れた所での置き控えだけ。安全弁として (a) の頭打ちも brush.wgsl に残す
4. **自動補充と組み合わせたときの吸い込み**: 自動補充 on では筆を下ろすたびに満タンへ戻るので、吸う場面はストロークの後半か置いたままのときに限られる。吸い込みを主に見せたいなら自動補充の既定を見直すか、筆が減る速さ(筆の大きさ)の既定を小さめにする
5. **wet-on-wet への影響**: 濡れた所へ塗ると差が小さく置く水が減るので、色の入り方・広がり方が変わる。e2e(wet-on-wet・グレージング・削り)の閾値と既定値の調整し直しが要る。どこまで今の描き味を保つかを決める
6. **記録の再生**: 受け渡しは GPU だけで進むので、再生も今と同じく画面と同じ経路で同じ結果になる。動かないフレームの splat は生ポインタ点の記録には残らないので、「置いたまま流れ出る」が再生で再現されない既知の制約は残る(記録側で「止まっていた刻み」も点として残せば解消できる)
